
# 第 2 章 位移控制混合仿真

本章描述和解释位移控制（DC）混合仿真，作为后续章节提出的不同类型混合仿真的背景。它定义了 DC 混合仿真。介绍了 DC 混合仿真的必要组成部分。解释了这些组成部分之间的相互作用。本章展示了 DC 混合仿真中一个积分时间步内通常发生的过程顺序。使用一个简单的单跨框架示例来说明本章提出的概念。最后总结了 DC 混合仿真的一些优点和局限性。

## 2.1 引言

DC 混合仿真是一种混合仿真类型，其中控制系统通过作动器等加载方式将位移施加到物理试件上。因此，“DC”指的是控制系统的控制模式。混合仿真通常以这种方式运行。这有助于实现相对透明和稳定的混合仿真运行，至少有两个原因。首先，大多数有限元分析（FEA）程序使用基于位移的公式。因此，施加到试件上的位移很容易获得。其次，控制系统通常设计为在 DC 模式下运行良好。因此，位移施加稳定且充分。

## 2.2 计算驱动程序

如第 1 章所述，在混合仿真过程中，结构的分析部分在计算驱动程序中数值建模和分析。在 DC 混合仿真期间，计算驱动程序向控制系统发送试验位移以施加到试件上。计算驱动程序可能会使用也可能不会使用来自控制系统的反馈值来推进到下一个时间步。这取决于为仿真部署的时间积分方案的类型。当使用反馈时，通常使用力反馈而不是位移反馈。

在单跨框架示例中，模型由两个柱（单元 1 和 2）和一个弹簧（单元 3）连接组成，如图 2.1 所示。每个柱的顶部放置一个集中质量。两个柱的底部是固定的。柱在轴向是刚性的，顶部可以自由旋转。旋转自由度被凝聚掉，只留下自由度 1 和 2。单元 2 和 3 与质量和阻尼一起在 FEA 软件中建模。为有限元分析选择时间积分方案和地震动。显式和预测-校正时间积分方法优于隐式方法，因为隐式方法的迭代性质。在依赖于路径的物理试件上进行迭代可能会在混合仿真中产生不切实际的结果。对于此示例，选择 αOS（算子分裂）时间积分方案。

## 2.3 物理传递系统

在 DC 混合仿真中，物理传递系统的作用是将计算驱动程序的试验位移施加到物理试件上。然后它将测量的反馈（位移和力）发送回计算驱动程序。一个典型的物理传递系统包括一个控制系统、数据采集（DAQ）系统以及包括被测试件在内的物理实验装置。测试试件代表结构中无法在计算驱动程序中良好建模的部分。

控制系统通常采用 PID 控制器来控制 DC 混合仿真的作动器，如图 2.2 所示。需要注意的是，积分器回路（Integrator Loop）的时钟速度与伺服控制回路（Servo-Control Loop）不同。伺服控制回路以固定的时钟速度运行，而积分器回路的时钟速度则根据给定时间步分析的复杂性而变化。控制系统的作用是弥合两个时钟速度之间的差距。

![](images/d8f4cb6fb78cc2ad35b433916bb750493fe738db8bb8f31125b6b836cf2cbac1.jpg)  
图 2.2：控制系统中用于 DC 混合仿真的控制回路。

克服这一困难的一种常见方法是让控制系统在收到下一个试验位移之前，对试验位移进行斜坡保持。虽然这种方法解决了问题，但它有一些缺点。一个主要缺点发生在控制系统在计算驱动程序计算下一个指令位移时长时间保持试验位移。由于试件的率相关特性和试件内部的应力松弛，这对结果产生了不利影响。斜坡时间也需要设置得当，以便控制系统有足够的时间以稳定的方式达到试验位移。同时，它不能太长以至于在收到下一个试验位移之前从未达到试验位移。

为了克服与斜坡保持方法相关的问题，Mosequeda [15] 开发并实施了一系列事件驱动的预测-校正方法。这是一个两阶段方法。它在斜坡保持方法保持先前指令位移的地方预测下一个试验位移，并在斜坡保持方法斜坡上升到新试验位移的地方进行校正以达到新的试验位移。它使用先前试验位移以及计算出的速度和加速度的外推多项式进行预测。如果计算驱动程序花费相对较长的时间来发送下一个试验位移，此方法最终会保持最后计算出的预测位移，以避免不切实际的预测。

当从计算驱动程序收到下一个试验位移时，此方法使用先前试验位移、计算出的速度和加速度以及新试验位移构成的插值多项式进行校正以达到新的试验位移。使用 0、1、2 和 3 次多项式的组合实现了不同的预测-校正方法。避免使用更高次多项式，因为它们会产生不必要的振荡，并且需要太多的历史数据。在卸载时，那么长的历史是无关紧要的。预测-校正方法提供了平滑连续的作动器运动，这对于混合仿真是理想的。在 nees@berkeley 实验室，这些预测-校正方法是使用 Mathworks Simulink 和 Stateflow 模型结合 xPC 实时操作系统实现的。关于 nees@berkeley 实验室的更多信息可以在附录 B 中找到。

DAQ 系统在测试过程中收集和记录数据。载荷传感器（LC）和线性可变差动变压器（LVDT）分别测量力和位移。这些测量到的力和位移可以反馈给计算驱动程序。这些测量值位于作动器坐标系中，需要转换到单元坐标系才能被反馈。最后，实验装置通常包括载荷边界元件、作动器和 DAQ 设备。

在单跨框架示例中，单元 1 使用试件进行物理测试。使用 nees@berkeley 的 $\mu$-NEES 实验装置（图 2.3）。关于 $\mu$-NEES 实验装置和实验室的更多信息可以在附录 B 中找到。底部带有 U 形夹、顶部带有作动器的一个柱子是该示例的物理试件。xPC 实时操作系统与带有预测-校正方法的 MTS-STS 控制器一起使用。

## 2.4 OpenFresco 中间件混合仿真框架

OpenFresco 中间件的目的是协调计算驱动程序和物理传递系统之间的事务 [20]。计算驱动程序和物理传递系统之间的交互可能变得复杂。有几个因素需要考虑。第一个因素是通信方法，决定一个进程将如何与另一个进程通信。另外重要的是，来自计算驱动程序的试验位移可能不在适当的坐标系中，以便作动器施加到试件上。需要执行必要的转换，以确保试件被正确加载，并且反馈被计算驱动程序正确处理。与控制及 DAQ 系统的接口也可能成为挑战，因为每个控制和 DAQ 系统都有独特的接口。因此，需要一个第三系统来协调计算驱动程序和物理传递系统之间的交互。

在许多先前的情况下，这个第三系统是为每个混合仿真定制编程的。每个实验室或设备站点都有自己独特的方式进行混合仿真。这使得站点之间难以协作，特别是在多站点测试中。即使过程基本相同，接口不同，一个实验室也难以移植和修改另一个实验室的实现。OpenFresco 通过提供一个透明且易于扩展的混合仿真软件框架解决了这一难题。图 2.4 以绿色显示了 OpenFresco 抽象类。关于 OpenFresco 的深入讨论可以在附录 A 中找到。表 2.1 显示了如何为单跨框架示例配置 OpenFresco。随后的小节将详细解释这些设置。

### 2.4.4 xPC-Target 实验控制

单跨框架示例使用 xPC-Target 实验控制与控制系统通信。该实验控制使用 xPC-Target 应用程序接口（API）与运行 Simulink 预测-校正模型的 xPC-Target 计算机通信。如图 2.2 所示，OpenFresco 和 xPC-Target 计算机通过 TCP/IP 连接通信。xPC-Target 计算机和 PID 控制器位于 SCRAMNet 环上，这是一种共享内存网络。xPC-Target 上运行的预测-校正算法生成的位移几乎可以瞬间通过 SCRAMNet 被 PID 控制器看到。这允许两个进程之间实现瞬时和确定性的通信。

## 2.5 DC 混合仿真的顺序过程

本节按顺序列出了 DC 混合仿真在积分时间步 n 的过程。它详细解释了每个过程，并展示了计算驱动程序、OpenFresco 中间件和物理传递系统如何相互作用。每个过程都应用于单跨框架示例以帮助解释。本节不涵盖负责初始化和结束仿真的过程。仅突出显示 OpenFresco 具体类中的关键方法。图 2.8 中的 UML（统一建模语言）序列图显示了当计算驱动程序或仿真应用程序设置试验响应时，在 OpenFresco 类中调用的方法序列。图 2.8 对应过程 1 到 5，并相应标记。图 2.9 显示了当仿真应用程序试图获取抵抗力时调用的方法。图 2.9 对应过程 6 到 10，并相应标记。

**1. 计算驱动程序计算预测速度 $( \widetilde { \dot { \bf u } } _ { n } )$ 和位移 $( \widetilde { \mathbf { u } } _ { n } )$ 向量。**

单跨框架使用质量矩阵（M）、粘性阻尼矩阵（C）和切线刚度矩阵 $\mathbf { \eta } ( \mathbf { K } )$ 在 FEA 软件中建模。此示例使用 αOS 时间积分方案。αOS 时间积分方案基于 Hiber-Hughes-Talyor（HHT）运动方程（方程 2.1）[9]。$\ddot { \mathbf { u } } _ { i }$、$\dot { \mathbf { u } } _ { i }$、${ \bf { u } } _ { i }$ 和 $\mathbf { f } _ { i }$ 分别是时间步 $i$ 的节点加速度、速度、位移和荷载向量。$\mathbf { r } ( \mathbf { u } _ { i } )$ 是以 ${ \bf u } _ { i }$ 为输入的节点抵抗力向量函数。当前时间步 $n$ 和上一个时间步 $n - 1$ 在方程 2.1 中使用。其中 $\mathfrak { Q } \in [ 2 / 3 , 1 ]$ 是用户选择的参数，允许调整数值阻尼。

$$
\begin{array}{l} \mathbf {M} \ddot {\mathbf {u}} _ {n} + \alpha \mathbf {C} \dot {\mathbf {u}} _ {n} + (\alpha - 1) \mathbf {C} \dot {\mathbf {u}} _ {n - 1} + \alpha \mathbf {r} (\mathbf {u} _ {n}) + (\alpha - 1) \mathbf {r} (\mathbf {u} _ {n - 1}) \\ = \alpha \mathbf {f} _ {n} + (\alpha - 1) \mathbf {f} _ {n - 1} \quad (2. 1) \\ \end{array}
$$

αOS 方法使用时间步 $n$ 和 $n-1$ 之间位移、速度和加速度的 Newmark 关系。方程 2.2 估计时间步 n 的速度。它可以组织为两部分之和，如方程 2.3。第一部分是预测速度，其中 $\tilde { \dot { \mathbf { u } } } _ { n } = \dot { \mathbf { u } } _ { n - 1 } + \Delta t ( 1 - \gamma ) \ddot { \mathbf { u } } _ { n - 1 }$。第二部分是校正项。

$$
\begin{array}{l} \dot {\mathbf {u}} _ {n} = \dot {\mathbf {u}} _ {n - 1} + \Delta t (1 - \gamma) \ddot {\mathbf {u}} _ {n - 1} + \Delta t \gamma \ddot {\mathbf {u}} _ {n} (2.2) \\ = \tilde {\mathbf {u}} _ {n} + \Delta t \gamma \ddot {\mathbf {u}} _ {n} (2.3) \\ \end{array}
$$

![](images/59628fed13aeec3277631b5c73e028e76b9ce0f5a53616cb0bfe18fa05e4b5c7.jpg)  
图 2.8：本地测试期间设置试验响应时 OpenFresco UML 序列图。

![](images/a687bdb410fd4a78fb2a2dcdf3053190785d329e5b0201c3ae04f5759578cc85.jpg)  
图 2.9：本地测试期间获取抵抗力时 OpenFresco UML 序列图。

方程 2.4 近似时间步 n 的位移。它同样可以组织为预测部分和校正部分之和。预测位移为 $\widetilde { \mathbf { u } } _ { n } = \mathbf { u } _ { n - 1 } + \Delta t \dot { \mathbf u } _ { n - 1 } + ( \Delta t ) ^ { 2 } ( 1 / 2 - \beta ) \ddot { \mathbf u } _ { n - 1 }$。

$$
\begin{array}{l} \mathbf {u} _ {n} = \mathbf {u} _ {n - 1} + \Delta t \dot {\mathbf {u}} _ {n - 1} + (\Delta t) ^ {2} (1 / 2 - \beta) \ddot {\mathbf {u}} _ {n - 1} + (\Delta t) ^ {2} \beta \ddot {\mathbf {u}} _ {n} (2.4) \\ = \tilde {\mathbf {u}} _ {n} + (\Delta t) ^ {2} \beta \ddot {\mathbf {u}} _ {n} (2.5) \\ \end{array}$$

需要注意的是，这些预测速度和位移是根据上一个时间步 $n - 1$ 的已知速度和位移计算得出的。$\beta$ 和 $\gamma$ 根据选定的 α 值通过方程 2.6 计算。

$$
\beta = \frac {(2 - \alpha) ^ {2}}{4} \quad \gamma = \frac {(3 - 2 \alpha)}{2} \tag {2.6}
$$

校正步骤在过程 10 中执行。在此步骤中，计算驱动程序仅计算 $\widetilde { \dot { \mathbf { u } } } _ { n }$ 和 $\widetilde { \mathbf { u } } _ { n }$。

**2. 实验单元将预测位移向量 $( \widetilde { \mathbf { u } } _ { n } )$ 转换为试验位移向量 $( \widehat { \mathbf { u } } _ { n } )$ 并将 $\hat {  { \mathbf { u } } } _ { n }$ 发送到实验装置。**

在计算驱动程序上运行的 FEA 软件中的双节点连接实验单元将过程 1 中计算的预测位移向量 $( \widetilde { \mathbf { u } } _ { n } )$ 转换为基本实验单元坐标系中的试验位移向量 $( \widehat { \mathbf { u } } _ { n } )$。在此示例中，它获取图 2.1 中单跨框架模型自由度 1 处的节点位移，并将其转换为图 2.5 所示双节点连接单元 2 方向的试验位移。由于这是一维单元，转换很简单。向量 $\hat {  { \mathbf { u } } } _ { n }$ 只有一个条目。转换完成后，双节点连接单元通过本地实验站点将 $\hat {  { \mathbf { u } } } _ { n }$ 发送到单作动器实验装置。双节点连接对象使用 update 方法调用本地站点对象的 setTrialResponse 公共方法。该 setTrialResponse 方法调用单作动器对象的 setTrialResponse 公共方法。

**3. 实验装置将试验位移向量 $( \widehat { \mathbf { u } } _ { n } )$ 从基本实验单元坐标系转换到作动器坐标系，并将转换后的试验位移向量 $( \breve { \mathbf { u } } _ { n } )$ 发送到实验控制。**

单作动器实验装置从双节点连接单元接收 $\hat {  { \mathbf { u } } } _ { n }$。它将 $\hat {  { \mathbf { u } } } _ { n }$ 转换到作动器坐标系，并组装新的试验位移向量 $( \breve { \mathbf { u } } _ { n } )$，如图 2.7 所示。此转换在单作动器对象的 setTrialResponse 方法中执行，该方法调用受保护的 transfTrialResponse 方法。然后，它通过调用 xPC-Target 对象的 setTrialResponse 公共方法，将 $\breve { \mathbf { u } } _ { n }$ 发送到 xPC-Target 实验控制。对于此示例，实验单元和实验装置中的转换设计得非常简单。然而，根据模型和设置的不同，这些转换可能会变得复杂。OpenFresco 可以对这两个过程执行线性和非线性转换。

**4. 实验控制将转换后的试验位移向量 $( \breve { \mathbf { u } } _ { n } )$ 发送到控制系统。**

xPC-Target 实验控制通过 TCP/IP 连接将来自单作动器实验装置的 $\breve { \mathbf { u } } _ { n }$ 发送到 xPC-Target 计算机（图 2.2），通过调用 xPC-Target 对象的受保护 control 方法。xPC-Target 的 setTrialResponse 方法调用 control 方法。除了发送 $\breve { \mathbf { u } } _ { n }$ 外，control 方法还告知 xPC-Target 已发送新的指令位移，并指示预测-校正算法从预测位移切换到开始校正到新的试验位移。

**5. 控制系统施加试验位移。**

在 xPC-Target 上运行的预测-校正模型开始校正到新的试验位移 $\breve { \mathbf { u } } _ { n }$。MTS-STS 控制器通过 SCRAMNet 看到校正位移。控制器通过 $\mu \cdot$ -NEES 实验装置（图 2.3）中的作动器施加这些位移。一旦达到新的试验位移 $\breve { \mathbf { u } } _ { n }$，预测-校正算法从校正切换到预测。这些位移再次由 MTS-STS 控制器和 $\mu$-NEES 装置施加到试件上。预测-校正算法继续预测，直到收到下一个试验位移 $\breve { \mathbf { u } } _ { n + 1 }$。如果 $\breve { \mathbf { u } } _ { n + 1 }$ 未能及时到达，预测-校正算法将进入减速模式。它最终会保持最后计算出的预测位移，直到 $\breve { \mathbf { u } } _ { n + 1 }$ 到达。

**6. DAQ 系统测量位移和力。**

DAQ 系统分别通过 LVDT 和 LC 测量位移和力。LVDT 和 LC 是 $\mu \cdot$ -NEES 实验装置的一部分。PID 控制器使用这些反馈作为其闭环控制系统的一部分。控制器还将它们写入 SCRAMNet，以便 xPC-Target 记录并将其反馈给 xPC-Target 实验控制。

**7. 实验控制从 DAQ 系统读取测量位移 $( \bar {  { \mathbf { u } } } _ { n } )$ 和力 $( { \overline { { \mathbf { f } } } } _ { n } )$，并将 ${ \bar {  { \mathbf { u } } } } _ { n }$ 和 $\mathbf { \overline { { f } } } _ { n }$ 发送到实验装置。**

xPC-Target 实验控制首先检查试验位移是否已被控制系统施加，即是否已完成对新的试验位移的校正。如果试验位移已施加，xPC-Target 实验控制读取在施加试验位移时的测量位移 $( \bar {  { \mathbf { u } } } _ { n } )$ 和力 $( { \overline { { \mathbf { f } } } } _ { n } )$。这两个操作都在 xPC-Target 对象的 acquire() 受保护方法中执行。acquire 方法在 xPC-Target 对象的 getDaqResponse 公共方法中被调用。该 getDaqResponse 方法由单作动器对象的 getDaqResponse 公共方法调用。

**8. 实验装置将测量位移 $( \bar {  { \mathbf { u } } } _ { n } )$ 和力 $( { \bar { \bf f } } _ { n } )$ 从作动器坐标系转换到基本单元坐标系，并将转换后的力 $( { \check { \mathbf { f } } } _ { n } )$ 向量发送到实验单元。**

单作动器实验装置从 xPC-Target 实验控制接收 $\bar {  { \mathbf { u } } } _ { n }$ 和 $\mathbf { \overline { { f } } } _ { n }$。它将作动器坐标系中的 $\bar {  { \mathbf { u } } } _ { n }$ 和 $\mathbf { \overline { { f } } } _ { n }$ 转换为基本实验单元坐标系中的 $\check {  { \mathbf { u } } } _ { n }$ 和 $\mathbf { \check { f } } _ { n }$。这是过程 3 中转换的逆转换。单作动器 getDaqResponse 方法调用私有的 transfDaqResponse 方法执行转换。单作动器 getDaqResponse 方法由本地站点对象的 checkDaqResponse 公共方法调用。checkDaqResponse 方法检查这是否是第一次调用此方法。如果是，它调用单作动器 getDaqResponse 方法。checkDaqResponse 方法由本地站点对象的 getForce 公共方法调用。

**9. 实验单元将测量力 $( { \check { \mathbf { f } } } _ { n } )$ 从基本实验单元坐标系转换到全局坐标系，并将力 $\mathbf { r } ( \widetilde { \mathbf { u } } _ { n } )$ 反馈给计算驱动程序。**

双节点连接实验单元从单作动器装置获取 $\check { \mathbf { f } } _ { n }$。它将基本实验单元坐标系中的 $\check { \mathbf { f } } _ { n }$ 转换为全局坐标系中的 $\mathbf { r } ( \widetilde { \mathbf { u } } _ { n } )$。这是过程 2 的逆转换。然后 $\mathbf { r } ( \widetilde { \mathbf { u } } _ { n } )$ 被反馈给在计算驱动程序上运行的 FEA 程序。$\check { \mathbf { f } } _ { n }$ 通过双节点连接对象的 getResistingForce 公共方法获取，该方法调用本地站点对象的 getForce 方法。然后 getResistingForce 执行向全局坐标系的逆转换。

**10. 计算驱动程序使用测量力 $( \mathbf { r } ( \widetilde { \mathbf { u } } _ { n } ) )$ 并前进到时间步 $n + 1$。**

αOS 方法使用方程 2.7 来近似方程 2.1 中的 $\mathbf { r } ( \mathbf { u } _ { n - 1 } )$。

## 2.6 DC 混合仿真的优点与局限性

与其他控制模式相比，在控制系统处于 DC 模式下进行混合仿真有其优点。首先，DC 混合仿真的公式与大多数 FEA 程序一致。大多数 FEA 程序使用基于位移的方法来求解静态和动态问题。让计算驱动程序向控制系统发送位移并使用测得的力作为反馈，与 FEA 程序从全局层面到单元层面再回到全局层面的处理方式配合得很好。其次，大多数控制和加载系统设计为在位移或位置控制下运行良好。因此，让这些系统在力控制下运行则困难得多。最后，混合仿真中的大部分工作都是在 DC 混合仿真中完成的。因此，使用其他控制模式的开创性研究不多，使得其他类型的混合仿真困难得多。

然而，这并不意味着 DC 混合仿真没有缺点。有些试件无法在 DC 下进行良好测试。如果试件在加载方向上非常刚硬，DC 就不够用了。这种类型的试件在结构工程中非常常见。它出现在剪力墙的侧向方向或梁柱的轴向方向。另一种情况是快速或实时混合仿真。当以相对较高的速度运行混合仿真时，必须考虑试件和加载系统的惯性效应。DC 在这种情况下是不够的。还有其他测试情况需要在仿真过程中切换控制模式。最初非常刚硬随后表现出软化行为的试件可能需要在初始阶段采用力控制，在后期切换到 DC。一个实验装置可能需要同时激活多种控制模式。以梁柱为例，轴向加载可能是力控制，而侧向可能是 DC，两者同时进行。因此，存在探索混合仿真中其他控制策略的需求。
